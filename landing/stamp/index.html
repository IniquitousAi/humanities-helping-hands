When did these files exist?

Every file here gets a stamp. A computer makes a code from each file. It puts the code in a public ledger. Nobody can change a page later without us seeing it. You can check the 256 number code yourself.

Every build of this site, with the Lean files behind its proofs, is fingerprinted (a 256-bit code) and the fingerprint is written into Bitcoin. Nobody can change a file afterward without the fingerprint showing it. You can check it yourself, without trusting us.

Each static deployment generates cryptographic SHA-256 digests across all repository assets and formal Lean verification files. These hashes are anchored into the Bitcoin blockchain via OpenTimestamps, establishing a non-repudiable timestamp without trusted intermediaries.

I.The two files

LIST

manifest.txt: one line per file, its sha256 fingerprint and its path.

PROOF

manifest.txt.ots: the OpenTimestamps proof that the list existed by a Bitcoin block.

II.Check it in three steps

1

Download both files into one folder.

2

Install the OpenTimestamps client: pip install opentimestamps-client. Or, with no install, drop the .ots file on the OpenTimestamps website (opentimestamps.org).

3

Run ots verify manifest.txt.ots. It names the Bitcoin block and its time. A new build can say "pending" for a few hours, until Bitcoin confirms it.

This shows the file is real and old. It does not prove who wrote it. It does not prove if the text is right. That is why we run computer checks on every math fact.

What this proves: the list, and so every file named in it, existed no later than that block. What it does not prove: who wrote a file, or that a file is right. Being right is what the labels and the checkers are for.

Cryptographic timestamping attests solely to prior existence prior to block confirmation time; it does not assert authorship, semantic correctness, or formal validity. Proof validation is performed deterministically by kernel verifiers.
